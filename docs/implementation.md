# TailorMouse 0.2 implementation and validation

Version 0.2.5 removes the cursor-warp correction after physical use of 0.2.4 caused difficult movement and slider dragging. Native movement passes through untouched. A separate explicit USB DPI control backs up, writes, reads back and recovers the original wired Naga Pro's live sensitivity. A runtime check using the same transport code verified 3200 → 1600 → 3200 DPI and unchanged persisted DPI. That historical DPI control has been replaced in the UI by the 0.2.8 native tracking sliders.

Version 0.2.6 replaces the sidebar layout with a compact dark tabbed window based on the user's screenshots. The top row contains Start/Stop, profile selection, Edit and device selection. Button assignments initially used eight ordinary-button rows and two side-panel pages. Version 0.3.0 retains the side panels and shows extra ordinary rows only after real input identifies them. The modifier strip chooses mappings, and a separate editor keeps edits in a local draft until OK; Cancel discards them. Default restoration and inherited modifier mappings remain available. Other tabs retain wheel, chord, calibration and input activity controls; 0.2.8 adds native tracking sliders. The first launch adopts a 680×510 content size before preserving future user resizing. The mouse illustration is independently drawn vector artwork. No input engine or profile schema changed. A separate AppKit renderer uses an in-memory preview model and exports ignored PNGs without reading/writing user settings, runtime status, activating interception or writing hardware.

Version 0.2.7 adds direct original-Naga Bluetooth side-button input after HID reports were observed without Quartz keyboard events. The [Bluetooth report investigation](research/bluetooth-runtime.md) documents scope, capture replay, deduplication, matched holds and recovery. The listener is active only after Start and uses shared device access; discovery itself stays metadata-only.

The user requested an original recreation and installation after the static research milestone. This document describes TailorMouse behavior, not recovered SteerMouse source or verified feature parity.

## Implemented behavior

Profiles include button bindings, exact modifier combinations, side-button chords, separate discrete wheel axes. Legacy pointer-gain fields remain readable but are inactive. Naga product IDs `0x008f`, `0x0090`, and `0x0092` under vendor `0x1532` share `razer.naga.pro`; connection-specific state remains separate so one mouse cannot complete another mouse's chord. One profile set follows those transports. Device discovery enumerates metadata without opening/seizing HID devices or registering input report callbacks.

By default, mappings fire complete shortcut/click pairs on press. Chord prefixes defer their individual actions until resolved; an unmatched prefix replays its captured single action. Repeated physical downs cannot duplicate an action. A press retains its original mapping across profile switches and edits. Stop, tap disable, permission loss, manager conflict and device disappearance clear internal state and release posted held outputs. Changing the selected device family stops active handling.

Version 0.3.5 adds per-binding shortcut behavior: Press once (the backward-compatible default), Hold until release, and Hold and repeat. Physical button and chord mappings can keep a shortcut key down; repeats are tagged key-down events with the autorepeat flag, followed by one final key-up. Repeat timing comes from AppKit's system [key repeat delay](https://developer.apple.com/documentation/appkit/nsevent/keyrepeatdelay) and [interval](https://developer.apple.com/documentation/appkit/nsevent/keyrepeatinterval). Wheel assignments remain complete taps because wheel ticks have no physical held state. A chord hold ends when either member is released; an unresolved prefix released before a chord decision replays a complete tap. Existing mappings and their press-time snapshots remain compatible.

The output tracker owns keys by connection-state instance and trigger button, coalesces simultaneous holds of the same key, skips missed timer bursts, and releases its own held outputs on Stop, disconnect, permission loss, manager conflict and normal app termination. No ordinary keyboard history is recorded. All 113 tests pass, including held C through receiver keyboard and Bluetooth report decoding, repeat timing, duplicate down/drag, press-time mapping snapshots, chord release/reset, multi-source ownership, extended function keys and recovery. Version 0.3.7 retains each held button's chord definitions after a completed match. A fresh down of another member can trigger the chord again while its anchor remains held, including alternating left/right click chords and either press order. Releases retain their original suppression decisions; held shortcut chords still emit a matched up when either member releases. Press-time chord definitions survive profile edits, and reset removes the retained anchors. This chord correction was deployed in 0.3.6; the user identified modifier selection as the remaining inconsistent part.

Naga keyboard, mouse and wheel mapping selection combines onboard event modifiers with a stable snapshot of the separate keyboard's modifier transitions. The snapshot is seeded at Start from the existing UI modifier observer and current hardware state, then updated synchronously by non-Naga `flagsChanged` events. TailorMouse-tagged events and Naga-generated modifier transitions cannot clear this snapshot. Stop/recovery resets it. This avoids both missing event flags and the polled HID table clearing between side-button reports, observed during the 0.3.6 test. Raw Bluetooth routing uses the same snapshot; ordinary keyboard text is neither logged nor remapped. Releases retain press-time modifiers, and Naga activity displays the effective modifier symbols.

Version 0.3.8 stores one wired Naga tracking reference for USB cable, USB receiver and Bluetooth. Previously each connection scaled its own starting resolution and inherited its own acceleration when the profile left acceleration unset. Read-only native snapshots found different receiver resolution and Bluetooth acceleration values; equal slider positions therefore did not request equal native tracking parameters. The reference is captured once from an unmodified wired service before applying profile gain. For this existing installation, a private migration reconstructed the reference resolution from the observed wired resolution multiplied by the active gain, preserving that wired target without scaling it twice. The reference persists separately from each connected service’s restoration snapshot. Application-specific gains still apply intentionally.

The tracking loop now compares actual service values with the desired values each poll, including when a receiver keeps its registry ID while its driver resets properties. Stop and selection changes resolve fresh service handles before restoring originals. The main Quit command explicitly stops processing before termination. Reset Tracking Adjustments clears the profile adjustments while retaining the shared reference. This changes native resolution/acceleration only; hardware DPI and pointer events are not transformed.

## Validation and remaining acceptance work

Repository `swift test` passes all 96 tests on this Mac. Coverage includes twelve Naga logical buttons in both default key banks, identity aliases, migration, configuration round trips, modifier fallback, matched down/up/drag across edits, repeats, chord snapshots, unmatched-prefix recovery, source isolation, reset, scrolling fractions, finite legacy speed limits, live-DPI packet validation, write bounds, backup-before-write ordering, no-op behavior, landed-write recovery and failed-recovery reporting. Diagnostic self-checks additionally validate read/write framing, reverse-order recovery after a simulated landed-write failure, no-op writes and private backup serialization without opening devices. Release packaging uses the host architecture and an ad hoc signature.

Metadata enumeration identified the attached Bluetooth Razer Naga Pro and its event-service candidates. This validates discovery only. UI and installation checks leave processing stopped; active physical-input checks are intentionally pending:

1. With TailorMouse permissions enabled and competing managers stopped by the user, verify ordinary buttons and side buttons 1–12 over Bluetooth, wired USB and receiver.
2. Confirm sender attribution on every transport, including separate USB keyboard interfaces and reconnects. Unknown or ambiguous attribution must pass through.
3. Verify app switching while holding a mapped button, modifier mappings, matched chord releases and incomplete chord recovery.
4. Verify wheel direction/speed, native pointer movement and slider dragging with handling stopped and Running. Change native acceleration and sensitivity, confirm comfortable movement, and verify Stop restores tracking. Confirm Stop restores button pass-through.
5. Confirm no duplicate actions, unexpected typing, permission-loss capture or resumed interception after tap disable.

Raw report decoding beyond original Naga Bluetooth keyboard report 6, automatic hardware initialization, button reports absent from macOS, custom acceleration curves, smooth-scroll synthesis, held-action dragging, SteerMouse-format import and complete target parity are not implemented. The original Bluetooth 10–12 and USB/dongle hardware issues are not claimed fixed.

Version 0.3.0 implements [Fix Request 2](fix-request-2.md): grouped manual hotkey selection, F1–F24 representation with explicit extended-key compatibility limits, and observed-only ordinary button rows. Existing profiles and native tracking/DPI behavior are preserved.

Notes decode optionally; no routing behavior changed. Rendering includes collapsed/expanded editor states and scrollable alternating table rows.
