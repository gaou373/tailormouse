# Chord button selection and recording — 0.3.1

The chord selectors show Left Click, Right Click and Middle Click explicitly. Twelve Naga side buttons are grouped in a submenu. Other choices appear only if observed from the selected mouse or already present in saved chords; the unconditional Button 4–32 list is gone. Hidden saved assignments remain intact.

First and Second each have a Record button. Clicking it stops TailorMouse handling, refreshes device metadata, and arms a temporary, scoped listen-only event tap plus the existing shared original-Naga Bluetooth reader. A button is assigned only after a down and matching up from the same endpoint; repeat downs, drags, unrelated releases and other sources cannot replace it. Ordinary keyboards and generated TailorMouse events are excluded. Assignment is deferred 150 ms beyond release to let Cancel and mouse-up UI processing finish before controls re-enable. Escape, Cancel, 15-second timeout, tab/profile disappearance and explicit Start/Stop cancel the pending capture. Recording never starts remapping automatically. UI previews disable monitoring. Custom onboard key sequences outside the existing default Naga key map are not newly decoded by this recorder.

Primary clicks are now valid chord members. If the first primary button has a native/default click assignment, its down, drag and up pass through while it is a chord candidate. A matched second button's complete pair is consumed and the chord action fires once. Unmatched native primary clicks are not replayed. Custom primary mappings retain the earlier deferred-single behavior. Press-time suppression and mapping snapshots survive edits; reset leaves native releases available. Chord order is a configuration aid; the router accepts either press order, and the first native primary click retains its ordinary effect.

## 0.3.2 table and sheet layout

The Chords tab now uses a fixed Chord / Function / Note header, alternating 39-point rows, gray assignment buttons, an internal vertical scroll area and a compact add/remove/edit footer, based on the user's reference screenshots. Click a function, double-click a row, or select it and choose Edit to open a separate 540-point action sheet. Its title, category picker, striped action preview and bottom Restore Defaults / Cancel / OK controls follow the reference layout.

First/Second selectors, Record, chord modifiers and a short note are available under Chord buttons & note. New chords open that section expanded. The sheet edits a local value; OK saves the entire chord, while Cancel leaves buttons, modifiers, action and note unchanged. Adding a chord also stays local until OK. Existing chords with more than two members retain all their selectors. Notes are optional and backward compatible; the editor limits new text to 160 characters and import validation permits up to 1000.

This update changes the UI and optional note storage. It does not add wheel-trigger chords or held-key repetition; existing button chord routing and one-action-per-press behavior are preserved. No SteerMouse assets or source are included.

## 0.3.13 scroll inputs

Both chord selectors now include a **Scroll** submenu with **Scroll Up**, **Scroll Down**, **Scroll Left** and **Scroll Right**. Choose a physical button in the other selector, assign the action and save. Hold the button while scrolling to run the action on each nonzero scroll event; the button stays reusable until released. Record also accepts a scroll direction from the selected mouse, without enabling remapping. Button recording still requires its matched release and cannot be replaced by a scroll during an unfinished press.

Scroll direction is taken before Wheel reversal/speed. A matching chord takes precedence over the ordinary Wheel assignment for that axis only; another axis and unassigned directions retain their existing Wheel behavior. Discrete and continuous input are supported; inertial momentum does not trigger chords. Shortcut output is always a complete tap per event, including imported hold/repeat bindings, because a scroll has no physical release. Primary-button anchors preserve native click/drag/release behavior. Current keyboard modifiers choose the chord variant, while chord definitions retain their anchor's press-time profile snapshot.

Persisted scroll IDs are 200–203 (up/down/left/right), distinct from ordinary and Naga side buttons. Chords require distinct inputs and at most one scroll direction; scroll-only combinations are invalid. Existing button chords and schema-3 configuration remain compatible. Stop, disconnect and reset discard scroll candidates without generating a stray single action or leaving an output held.
